## 3. Persistence Layer

### Frontend Prisma schema (`prisma/schema.prisma`)
Minimal — only `User`, `Tenant`, `Session`, `VerificationToken`, brokerage models (`Accreditation`, `Client`, `Declaration`), digital-twin models (`Zone`, `TwinNode`, `TwinEdge`, `Scenario`, `Run`, `TwinEvent`, `TwinAgent`, `AgentRun`, `Policy`), and `AuditEntry`.

**No `Workflow`, `WorkflowRun`, `SeedDataset`, `SeedRecord`, `WorkflowExecution`, `LoopIteration`, or `ExecutionLog` models.**

### Backend Prisma schema (`backend/prisma/schema.prisma`)
Full production schema. Contains:
- `Workflow` — `(tenantId, workflowId, version)` unique, `definition: Json`, `active: Boolean`
- `WorkflowRun` — `status: WorkflowRunStatus`, `input/output/error/steps: Json`, `startedAt/endedAt`
- `WorkflowRunStatus` enum — `QUEUED | RUNNING | SUCCEEDED | FAILED | AWAITING_APPROVAL | CANCELLED`
- `TwinScenario` / `TwinRun` / `TwinMetric` — digital twin simulation runs
- `Job` — generic job queue table (`queue`, `name`, `status`, `payload`, `attempts`, `maxAttempts`)
- `DomainEvent` — event bus table

**Missing from backend schema:** `SeedDataset`, `SeedRecord`, `LoopIteration`, `ExecutionLog` — these need to be added.

### tRPC router (backend)
`customAgents.orchestration` sub-router exposes:
- `listWorkflows` — list workflows by tenant
- `getWorkflow` — get workflow + definition
- `saveDraft` — upsert workflow definition
- `validate` — server-side validation
- `execute` — synchronous execution (returns steps inline)
- `listRuns` — paginated run history
- `getRun` — run detail with steps

**Gap:** `execute` is synchronous (returns steps inline). No seed-loop, no per-iteration persistence, no background job dispatch. Long-running executions will time out.

|---|---|
| Two workflow type systems: `lib/workflow/types.ts` (WorkflowDefinition v2) vs `components/workflow-studio/types/workflow.ts` (Zod-based v1) | The new studio uses the Zod types. ## 10. Summary

The repository has a **fully built React Flow studio** (`workflow-studio.tsx`) that is never mounted. It has a **complete tRPC execution router** (`customAgents.orchestration`) that runs synchronously. It has **no seed-loop domain model** (no `SeedDataset`, `SeedRecord`, `LoopIteration`). The TwinForge dashboard renders entirely static demo data.

The implementation plan is:
1. Add seed-loop schema to backend Prisma
2. Implement loop execution service + BullMQ worker
3. Implement `ExecutorClient` using tRPC
4. Mount new studio on brokerage page with real data
5. Wire TwinForge pages to real `TwinScenario`/`TwinRun` data
6. Add dev fixtures and tests
