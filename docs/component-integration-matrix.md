## Service and security boundaries

- Frontend typed procedures are declared in `lib/trpc/router.ts`; the NestJS backend router mounts domain services in `backend/src/trpc/trpc.router.ts`. Components should consume the typed tRPC client, never Prisma directly.
- Backend CRUD routers exist for WMS inventory, FIZ, and FCZ domains, but generic CRUD availability does not itself establish transactional stock movement, approval enforcement, or audit semantics.
- Tenant and record-level security must be verified in backend procedures. UI role and zone switchers are context controls, not permission enforcement.
- Digital-twin scenario/simulation procedures must stay separated from production mutations. Verify each client call before enabling write actions.
- Marketing lead capture components still need submission handlers, persistence, rate limiting, and failure states unless explicitly wired in their implementation.
